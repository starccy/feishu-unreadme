# feishu-unreadme


在 js 端屏蔽飞书消息的已读回执。即，自己在看到其他人发送的（私聊或群聊）普通消息后，
对方的视角也会保持在自己未读的状态。


## 使用方法

先确保飞书进程已经关闭，避免脚本执行时因文件占用导致报错。

终端下执行：

```bash
python main.py <飞书安装根目录>
```

脚本会解压 `webcontent/messenger.asar` 文件并修改里面的 js 文件。

修改成功后请重启飞书客户端。若发现飞书功能异常，请将修改后的 `messenger.asar` 删除，
并将 `messenger.asar.bak` 文件重命名回 `messenger.asar`。

若已经应用过旧补丁，需要基于现有原始备份重新生成补丁，可执行：

```bash
python main.py <飞书安装根目录> --repatch
```


## 原理

飞书客户端前端 js 会监听 DOM 事件并收集新消息的 messageId、会话已读位置和话题已读
位置，之后传给 native 层发送网络请求给服务器。普通浏览时，脚本会在传给 native 之前
同时清空消息列表、折叠消息列表和各类已读位置。

当自己成功发送消息后，脚本会给当前会话一个短时、一次性的已读上报许可。许可与会话 ID
绑定，其他会话不能消费；许可使用一次或超过 1.5 秒后失效。这样可以避免“已经回复，
对方仍看到未读”的异常状态，同时继续屏蔽之后收到的新消息。


## 行为说明

* 打开会话、滚动浏览：保持未读。
* 成功发送普通消息：仅当前会话放行下一次已读上报。
* 发送失败：不放行已读上报。
* 其他会话：不受当前会话的发送动作影响。
* 引用回复：属于发送消息，也会触发当前会话的一次放行。


## 已知问题 / TODO

毕竟只是在 js 层修改的逻辑，而非拦截网络请求等更加靠谱的方式。前端可能有多个入口
来进行消息已读回执的请求，导致在以下情况下对方会看到自己已读：

* 对一个消息贴表情
* 接收对方发送的文件
* 同一会话在 1.5 秒许可窗口内恰好收到新消息，该消息可能进入本次已读上报
* 在未应用本补丁的手机或其他客户端查看消息

此外要注意，飞书更新后会覆盖修改的文件，所以需要重新执行脚本来修改。
